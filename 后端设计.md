# 拾礼 · 后端设计草案

版本 v0.1 ｜ 2026-11-04 ｜ 对应原型 v1（17 屏）

> 实现说明（2026-11-11）：已落地版本在 `server/`，SQLite，12 张表、18 个接口，覆盖商品、身份、选品记录、资料四块。本文保留完整设计，支付、物流、发票单据等未实现的表暂不建。

## 0. 约定

- 数据库 MySQL 8.0，字符集 utf8mb4，排序 utf8mb4_0900_ai_ci
- 金额统一 DECIMAL(10,2)，不用 float
- 状态用 TINYINT，含义写在注释里，不用 ENUM，便于扩展
- 时间统一存 UTC，接口返回 ISO 8601
- 所有表带 created_at / updated_at
- 主键 BIGINT UNSIGNED 自增，对外不暴露，接口用 order_no 这类业务号

## 0.1 已定决策（2026-11-04）

| 决策 | 结论 | 对设计的影响 |
|---|---|---|
| 协议价 | **不启用** | 不建 org_price 表；售价只有参考价一个 |
| 额度 | **只展示，不抵扣** | 订单实付 = 商品总额，credit_amount 恒为 0 |
| 多商户 | **不做** | 不需要 EDI 许可证、分账、结算；org 只是客户档案 |
| 发票 / 库存 / 退款 / 定制 / 等保 | 暂定 | 按第 8 节的默认方案推进，接入前再确认 |

## 0.2 范围调整：不做线上交易（2026-11-04）

本期定位是**选品工具**，不做支付、订单、退款。

**保留**

- 商品、品牌、分类、搜索、筛选
- 选品单（原清单）
- 企业、身份、白名单
- 地址、发票、对接人（资料展示）

**暂不启用**

- orders / order_item / payment / shipment / refund
- 额度抵扣、券核销
- 订单状态机、支付回调

**用「选品单」替代「订单」**

- selection：一次提交的选品记录
- selection_item：商品、数量、参考价快照

流程：加入选品单 → 提交 → 对接人线下跟进报价 → 成交走线下。

## 1. 领域模型

    微信用户 user
        │
        ├── membership（身份）── org（企业）
        │        ├── role = employee   员工
        │        ├── role = buyer      采购
        │        └── role = personal   个人（org_id = 0）
        │
        ├── cart_item（清单）
        ├── address（地址）
        ├── invoice（发票）
        └── order（订单）── order_item
                        └── payment

核心判断：**权限和价格由 membership 决定，不由 user 决定**。

一个人可能同时是 A 银行员工、B 企业采购、普通消费者，切换身份本质是切换 membership_id。

## 3. 接口约定

**Base**：https://api.yourdomain.com/api/v1

**鉴权**：Authorization: Bearer <token>，token 由 wx-login 换取，有效期 7 天，可续期

**统一返回**

    {
      "code": 0,
      "message": "ok",
      "data": {}
    }

**错误码**

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 未登录或 token 失效 |
| 1002 | 无权限 |
| 1003 | 参数错误 |
| 2001 | 商品不存在或已下架 |
| 2002 | 库存不足 |
| 3001 | 订单不存在 |
| 3002 | 订单状态不允许该操作 |
| 3003 | 重复提交 |
| 4001 | 支付失败 |
| 5000 | 服务端异常 |

**分页**

请求 page / pageSize（默认 1 / 20，上限 100），返回 list / total / page / pageSize

**金额**

统一返回字符串，如 "168.00"，避免 JS 浮点误差

**幂等**

下单接口必须带 Idempotency-Key（前端生成 UUID），重复提交返回同一订单

## 4. 接口清单

### 4.1 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /auth/wx-login | 传 code，返回 token / user / memberships |
| POST | /auth/phone | 传手机号授权 code，绑定并自动匹配白名单 |
| POST | /auth/bind-code | 用企业邀请码绑定身份 |
| POST | /auth/apply-buyer | 申请采购身份，进入待审批 |
| GET | /auth/me | 当前用户、全部身份、当前身份 |
| POST | /auth/switch | 切换 membership_id，返回新 token |

wx-login 返回示例：

    {
      "token": "eyJ...",
      "user": { "id": 1, "phone": null, "nickname": null },
      "memberships": [
        { "id": 11, "orgId": 1, "orgName": "明德银行", "role": "employee", "status": 1 }
      ],
      "current": 11
    }

### 4.2 商品与品牌

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /products | 关键词、品牌、分类、价格区间、排序、分页 |
| GET | /products/{id} | 详情，含图册、参数、库存 |
| GET | /brands | 品牌列表，按首字母分组 |

| GET | /search/hot | 热门搜索词（可选） |

/products 参数：keyword、brandId、categoryId、minPrice、maxPrice、sort（new/sales/priceAsc/priceDesc）、page、pageSize

## 5. 关键业务规则

### 5.1 价格

- 售价 = product.reference_price，所有身份一致，**没有协议价**
- 价格只在服务端算，前端不参与
- 下单时把 unit_price 快照进 order_item，之后改价不影响历史订单
- market_price 只作展示，必须有真实依据，不能编造

### 5.2 额度

额度只展示，不参与支付计算。

- 订单 pay_amount = 商品总额，credit_amount 恒为 0
- credit_log 只记录发放、到期、后台调整，不记消费
- 前端不得用额度做价格抵扣或「超出额度」提示
- 未来若要启用抵扣，再补事务扣减逻辑（见下方原方案）

启用抵扣时的参考写法（暂不实现）：

    BEGIN;
    SELECT credit_balance FROM membership WHERE id=? FOR UPDATE;
    UPDATE membership SET credit_balance = credit_balance - ?, credit_used = credit_used + ?;
    INSERT INTO credit_log (...);
    COMMIT;

### 5.3 订单状态机（本期不启用）

    0 待付款 ──支付成功──> 1 待发货 ──发货──> 2 待收货 ──确认──> 3 已完成
       │                                        │
       └──超时 30 分钟 / 用户取消──> 4 已取消     └──后台退款──> 5 已退款

每次状态变更写 audit_log，并触发订阅消息。

### 5.4 支付回调

1. 验签（微信支付平台证书）
2. 按 out_trade_no 查 payment，已成功则直接返回 SUCCESS
3. 更新 payment.status、transaction_id
4. 更新订单状态为待发货
5. 写 audit_log
6. 返回 SUCCESS

回调必须幂等，微信会重试最多 8 次。

### 5.5 库存

- 推荐：下单预占，支付后实扣，取消释放
- 简化版：支付成功才扣减，需接受少量超卖
